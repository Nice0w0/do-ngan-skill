# คิวรอรีวิว (ฝั่งคนตรวจ)

กติกาของดูงาน: งานเสร็จต้องผ่านคนตรวจ — skill นี้คือที่เดียวที่ตั้ง `done` เป็นปกติ **เมื่อคนตรวจบอกว่าผ่าน**

## 1. รวบรวมคิว

- ขอบเขต: ไม่ระบุ = ทั้งบริษัทที่ผู้ใช้เห็น · "ของฉัน" = งานที่ผู้ใช้ถือหรือสั่ง · "ทีม X" = ทีมนั้น (`list_teams`)
- งาน: `list_tasks` `status: ["review"]` (+ `assignee` / `project` ตามขอบเขต)
- แถวในแผ่นงาน: งานที่มีแผ่นงาน (`get_task` บอกยอด) → `read_sheet` เก็บแถวสถานะ "รอรีวิว"
- `list_notifications` — งานที่ระบบแจ้งว่ารอผู้ใช้รีวิว ให้ขึ้นก่อน

## 2. แสดงคิว

```
รอรีวิว 3 งาน · 7 แถวในแผ่นงาน

งาน
1. แก้หน้าล็อกอิน — ปอนด์ · รอมา 2 วัน
แผ่นงาน "บั๊กเว็บลูกค้า"
2. แถว 5 ปุ่มบันทึกไม่ทำงานบนมือถือ · หน้า ตั้งค่า · commit a1b2c3d
...
```
เรียงจากรอนานสุด · ไม่แสดง id

## 3. ไล่ตรวจทีละข้อ

สำหรับข้อที่ผู้ใช้เลือก (หรือไล่จากข้อ 1):
- แสดงรายละเอียด: `get_task` (รายละเอียด ประวัติ % กิจกรรมล่าสุด) หรือข้อความแถว + หมายเหตุ
- มี commit และอยู่ใน repo ที่เปิดอยู่ → `git show --stat <hash>` แล้วสรุปสิ่งที่แก้ 2–3 บรรทัด (ไม่เทโค้ดทั้งก้อน เว้นผู้ใช้ขอ)
- ถามคนตรวจ: **ผ่าน / ตีกลับ / ข้าม**

## 4. บันทึกผล

| ผล | งาน | แถวในแผ่นงาน |
|---|---|---|
| ผ่าน | `set_task_status` → `done` | `update_sheet` `set` ช่องสถานะ → "เสร็จ" |
| ตีกลับ | `set_task_status` → `doing` + ขอเหตุผลจากคนตรวจ แล้วบอกผู้ถือ (ใส่ในรายละเอียดด้วย `update_task` หรือหมายเหตุของแถว) | ช่องสถานะ → "กำลังทำ" · ต่อท้ายหมายเหตุ `ตีกลับ: <เหตุผล>` |
| ข้าม | ไม่แตะ | ไม่แตะ |

- แถวหลายข้อในแผ่นเดียว → รวมผลแล้วส่ง `update_sheet` ครั้งเดียวตอนจบแผ่น (ลดโอกาสชนคนที่เปิดแผ่นอยู่)
- **ห้ามกดผ่านแทนคนตรวจ** — ต้องได้คำว่าผ่านต่อข้อ หรือคำสั่งชัด ๆ เช่น "ผ่านทั้งหมด"

## 5. สรุปท้าย
