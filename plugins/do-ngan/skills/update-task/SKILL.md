# แก้งาน

ขั้นแรกเสมอ: หา id ของงานด้วย `list_tasks` (`search`, `assignee`) หรือ `my_tasks` — เจอหลายใบให้ถาม

## เปลี่ยนสถานะ — `set_task_status`

| ผู้ใช้พูด | status |
|---|---|
| เริ่มทำแล้ว / กำลังทำ | `doing` |
| **เสร็จแล้ว / ทำครบแล้ว / ส่งแล้ว** | **`review` (รอรีวิว) เสมอ** |
| ให้เป็นเสร็จ / เสร็จสิ้น / ปิดงาน (สั่งชัด ๆ) | `done` |
| ย้อนกลับไปยังไม่เริ่ม | `open` |

ถ้าผู้ใช้ถืองานนั้น % จะขยับตามแบบหน้าเว็บ (รอรีวิว 99% · เสร็จ 100%)

## ปรับ % — `set_task_progress`

`progress` 0–100 และ `reason` = สิ่งที่ทำไป (ขึ้นในประวัติ) · ทำได้เฉพาะคนที่ถืองานใบนั้น

## แก้รายละเอียด — `update_task`

`text` `description` `lane` `priority` `start_date` `end_date` `visibility` — ส่งเฉพาะที่เปลี่ยน · `null` = ล้างค่า
"เลื่อนไปศุกร์หน้า" → แปลงเป็นวันที่จริงก่อน แล้วบอกวันที่ใหม่ให้ผู้ใช้เห็น

## มอบหมาย / เปลี่ยนผู้ถือ — `assign_task`

- `assignees` = **ผู้ถือชุดใหม่ทั้งหมด** (คนแรก = ผู้ถือหลัก) แทนที่ของเดิม
- "เพิ่มก้อยเป็นผู้ถือร่วม" → `get_task` ดูผู้ถือเดิมก่อน แล้วส่งเดิม + ก้อย
- "โอนให้บอส" → `["บอส"]` · "ปล่อยงานคืนกอง" → `[]` (เพิ่ม `to_folder: true` ถ้าอยากเก็บเข้าโฟลเดอร์)
- เปลี่ยนผู้ถือของงานคนอื่น → ทวนก่อนทำ

## ย้ายเข้า/ออกโปรเจค

`add_task_to_project` — `project` = ชื่อ/id · `null` = ถอดออก

## ลบงาน — `delete_task`

**ถามยืนยันทุกครั้ง** พร้อมชื่องาน และบอกว่าลบผ่านทางนี้กู้คืนไม่ได้ (บนเว็บ Ctrl+Z ได้)
ถ้าผู้ใช้แค่อยากเก็บงานออกจากสายตา เสนอ `review`/`done` หรือปล่อยเข้าโฟลเดอร์แทน
