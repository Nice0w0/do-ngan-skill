# ลงงานจากสิ่งที่เพิ่งทำ

## 1. ดูว่าทำอะไรไป

ใช้ข้อมูลที่มีอยู่แล้วในบทสนทนาก่อน ถ้าไม่พอค่อยดูจาก git:
- `git log --oneline -10` และ `git diff --stat` (รวมที่ยังไม่ commit)
- สรุปเป็นภาษาคนทั่วไป 1–2 ประโยค ไม่ใช่ชื่อไฟล์ — คนอ่านบนบอร์ดอาจไม่ใช่นักพัฒนา

## 2. หางานที่ตรงกัน

- `my_tasks` แล้วเทียบชื่อ/รายละเอียดงานกับสิ่งที่ทำ
- ไม่เจอ → `list_tasks` ค้นด้วยคำสำคัญ
- **เจอหลายใบหรือไม่แน่ใจ → ถามผู้ใช้** พร้อมรายชื่อผู้สมัคร ห้ามเดา
- ไม่มีงานที่ตรงเลย → ถามว่าจะสร้างงานใหม่ไหม (`create_task` ผู้ถือ = `me`)

## 3. อัปเดต

เสนอให้ผู้ใช้ดูก่อนในบรรทัดเดียว เช่น
`"แก้หน้าล็อกอิน" → รอรีวิว · 90% · เหตุผล: แก้การตรวจรหัสผ่านและเพิ่มข้อความแจ้งเตือนแล้ว รอทดสอบ`

ผู้ใช้ตกลงแล้วค่อยเรียก:
- `set_task_status` — **ตั้งเป็น `review` (รอรีวิว) เสมอ** แม้งานจะดูเสร็จครบแล้วก็ตาม
  เปลี่ยนเป็น `done` (เสร็จ) ได้กรณีเดียว คือผู้ใช้บอกเองชัด ๆ ว่าให้เป็นเสร็จ/เสร็จสิ้น/ปิดงาน
- `set_task_progress` — % พร้อมเหตุผลที่ได้จากข้อ 1 (ทำได้เฉพาะคนที่ถืองาน)
- ถ้างานมีแผ่นงานย่อยและสิ่งที่ทำตรงกับบางแถว → `read_sheet` แล้วเสนอแก้สถานะแถวนั้นด้วย `update_sheet`

## ห้าม

- ห้ามตั้ง `done` เอง — คำว่า "เสร็จแล้ว" ที่ผู้ใช้พูดถึงตัวโค้ด ไม่นับเป็นคำสั่งปิดงาน ให้ใช้ `review`
  ถ้าไม่แน่ใจว่าผู้ใช้ต้องการปิดงานจริงไหม ให้ตั้ง `review` แล้วถามทีหลัง
- ห้ามแปะ diff โค้ดหรือข้อมูลลับ (key, token, รหัสผ่าน) ลงในเหตุผลหรือรายละเอียดงาน
